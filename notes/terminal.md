# Шпаргалка: терминал и Git

## Терминал (PowerShell)

| команда | что делает |
|---|---|
| `cd папка` | перейти в папку (внутри текущей) |
| `cd ..` | на уровень вверх |
| `cd ..\..` | на два уровня вверх |
| `cd C:\Users\admin\Обучение` | перейти по полному пути, откуда угодно |
| `cd ~` | в домашнюю папку `C:\Users\admin` |
| `ls` | показать содержимое папки |
| `ls -Force` | то же + скрытые файлы и папки (например, `.git`) |
| `mkdir имя` | создать папку |
| `mkdir папка\подпапка` | создать сразу вложенные папки |
| `New-Item имя.py` | создать пустой файл (коротко: `ni имя.py`) |
| `code имя.py` | открыть файл в VS Code; если файла нет — создастся при сохранении (Ctrl+S) |
| `code .` | открыть текущую папку в VS Code |
| `mv старое новое` | переименовать файл или папку |
| `mv файл папка\` | переместить файл в другую папку |
| `cp откуда куда` | скопировать файл |
| `rm имя` | удалить файл (без корзины!) |
| `cat имя` | показать содержимое файла |

**Обозначения путей:** `.` — текущая папка, `..` — родительская папка.

**Пробелы в именах:** имя с пробелом берётся в кавычки — `mkdir "мои решения"`. Лучше вообще без пробелов: `my_solutions`.

### PowerShell vs Linux / Git Bash

| задача | PowerShell | Linux / Git Bash |
|---|---|---|
| создать файл | `New-Item имя` | `touch имя` |
| вложенные папки | `mkdir a\b` | `mkdir -p a/b` |
| удалить папку целиком | `rm папка -Recurse` | `rm -r папка` |
| разделитель в пути | `\` (но `/` тоже обычно работает) | `/` |

⚠ Не создавать файлы с кодом через `echo "..." > файл` в Windows PowerShell — сохранит в UTF-16, Python может не прочитать.

## Git

### Ежедневный цикл

```
git status                       # что изменилось (красное — не в индексе, зелёное — в индексе)
git diff                         # какие именно строки поменялись
git add файл                     # добавить конкретный файл в индекс
git add .                        # добавить все изменения
git commit -m "Глагол + что сделано"
git push                         # отправить коммиты на GitHub
```

Три зоны: **рабочая папка → индекс (`add`) → история (`commit`)**. `push` отправляет только коммиты — без коммита `push` скажет «Everything up-to-date».

### Смотреть историю

| команда | что делает |
|---|---|
| `git log --oneline` | коротко, по строке на коммит |
| `git log --oneline --graph --all` | с деревом веток |
| `git show --stat` | какие файлы вошли в последний коммит |
| `q` | выйти из просмотра (пейджер `less`, когда внизу `:` или `(END)`) |

### Ветки

| команда | что делает |
|---|---|
| `git branch` | список веток, `*` — текущая |
| `git switch -c имя` | создать ветку и перейти (старый вариант: `git checkout -b имя`) |
| `git switch имя` | перейти на существующую ветку |
| `git merge имя` | влить ветку `имя` в текущую |
| `git branch -d имя` | удалить ветку (после merge) |

Цикл работы с веткой: `switch -c task/...` → коммиты → `switch main` → `merge task/...` → `branch -d task/...` → `push`.

- Ветка — указатель на коммит, а не папка; создаётся для всего репозитория сразу.
- **Fast-forward** при merge — в `main` не было новых коммитов, указатель просто сдвинулся вперёд.
- **merge vs rebase:** пока использовать merge. Rebase переписывает коммиты — никогда для уже отправленных.

### Исправить ошибку

| ситуация | команда |
|---|---|
| поменять сообщение последнего коммита (до push!) | `git commit --amend -m "новое"` |
| убрать файл из индекса (изменения остаются) | `git restore --staged файл` |
| выбросить изменения в файле (необратимо!) | `git restore файл` |

### Сообщения коммитов

- Глагол в повелительной форме: «Добавить…», «Исправить…», «Отметить…»
- Конкретика: **что** и **о чём**, а не «изменения» или «правки»
- Не повторять одно и то же сообщение — должно отличаться в `git log`
- Абсолютные даты и номера недель, а не «на след. неделю»

### Если что-то пошло не так

- `Connection was reset` при push — сетевой сбой, просто повторить `git push`.
- `LF will be replaced by CRLF` — безвредное предупреждение про окончания строк.
