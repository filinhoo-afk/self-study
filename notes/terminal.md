# Шпаргалка: терминал и Git

## Терминал (PowerShell)

| команда | что делает |
|---|---|
| `cd папка` | перейти в папку (внутри текущей) |
| `cd ..` | на уровень вверх |
| `cd ..\..` | на два уровня вверх |
| `cd C:\Users\admin\Обучение` | перейти по полному пути, откуда угодно |
| `cd ~` | в домашнюю папку `C:\Users\admin` |
| `ls` | показать содержимое папки |
| `ls -Force` | то же + скрытые файлы и папки (например, `.git`) |
| `mkdir имя` | создать папку |
| `mkdir папка\подпапка` | создать сразу вложенные папки |
| `New-Item имя.py` | создать пустой файл (коротко: `ni имя.py`) |
| `code имя.py` | открыть файл в VS Code; если файла нет — создастся при сохранении (Ctrl+S) |
| `code .` | открыть текущую папку в VS Code |
| `mv старое новое` | переименовать файл или папку |
| `mv файл папка\` | переместить файл в другую папку |
| `cp откуда куда` | скопировать файл |
| `rm имя` | удалить файл (без корзины!) |
| `cat имя` | показать содержимое файла |

### Запуск Python-файла

| команда | что делает |
|---|---|
| `python имя.py` | запустить файл из **текущей** папки |
| `python папка\имя.py` | запустить файл по пути от текущей папки (из корня `Обучение`: `python stepik\lists\имя.py`) |

`can't open file ... No such file or directory` — Python не нашёл файл по написанному пути: терминал стоит не в той папке или путь неполный. В тексте ошибки виден путь, который он искал.

### Чтение файлов и конвейер `|`

`cat` в PowerShell — псевдоним `Get-Content`.

| команда | что делает |
|---|---|
| `cat -Tail 5 файл` | последние 5 строк файла (`-TotalCount 5` — первые 5) |
| `cat -Encoding UTF8 файл` | прочитать файл как UTF-8 |
| `команда1 \| команда2` | конвейер: вывод левой команды — вход правой |
| `cat -Encoding UTF8 файл \| Select-String print` | оставить только строки, где есть `print` (аналог `grep`, шаблон — регулярное выражение) |

⚠ Кракозябры вида `РЈСЃР»РѕРІРёРµ` в выводе `cat` — не порча файла: VS Code сохраняет UTF-8, а Windows PowerShell 5.1 читает файл без BOM в старой кодировке. Лечится `-Encoding UTF8`.

**Обозначения путей:** `.` — текущая папка, `..` — родительская папка.

**Пробелы в именах:** имя с пробелом берётся в кавычки — `mkdir "мои решения"`. Лучше вообще без пробелов: `my_solutions`.

### PowerShell vs Linux / Git Bash

| задача | PowerShell | Linux / Git Bash |
|---|---|---|
| создать файл | `New-Item имя` | `touch имя` |
| вложенные папки | `mkdir a\b` | `mkdir -p a/b` |
| удалить папку целиком | `rm папка -Recurse` | `rm -r папка` |
| разделитель в пути | `\` (но `/` тоже обычно работает) | `/` |

⚠ Не создавать файлы с кодом через `echo "..." > файл` в Windows PowerShell — сохранит в UTF-16, Python может не прочитать.

## Git

### Ежедневный цикл

```
git status                       # что изменилось (красное — не в индексе, зелёное — в индексе)
git diff                         # какие именно строки поменялись
git add файл                     # добавить конкретный файл в индекс
git add .                        # добавить все изменения
git commit -m "Глагол + что сделано"
git push                         # отправить коммиты на GitHub
```

Три зоны: **рабочая папка → индекс (`add`) → история (`commit`)**. `push` отправляет только коммиты — без коммита `push` скажет «Everything up-to-date».

### Смотреть историю

| команда | что делает |
|---|---|
| `git log --oneline` | коротко, по строке на коммит |
| `git log --oneline --graph --all` | с деревом веток |
| `git show --stat` | какие файлы вошли в последний коммит |
| `q` | выйти из просмотра (пейджер `less`, когда внизу `:` или `(END)`) |

### Ветки

| команда | что делает |
|---|---|
| `git branch` | список веток, `*` — текущая |
| `git switch -c имя` | создать ветку и перейти (старый вариант: `git checkout -b имя`) |
| `git switch имя` | перейти на существующую ветку |
| `git merge имя` | влить ветку `имя` в текущую |
| `git branch -d имя` | удалить ветку (после merge) |

Цикл работы с веткой: `switch -c task/...` → коммиты → `switch main` → `merge task/...` → `branch -d task/...` → `push`.

- Ветка — указатель на коммит, а не папка; создаётся для всего репозитория сразу.
- **Fast-forward** при merge — в `main` не было новых коммитов, указатель просто сдвинулся вперёд.
- **merge vs rebase:** пока использовать merge. Rebase переписывает коммиты — никогда для уже отправленных.

### Что в `git status`

| вид | значит |
|---|---|
| `?? файл` | untracked: новый файл, Git за ним ещё не следит (лежит только в рабочей папке) |
| ` M файл` | modified: отслеживаемый файл изменён, но не добавлен в индекс |

Красным показаны файлы не в индексе, зелёным — в индексе.

### `.gitignore` и проверка игнора

- В `.gitignore` — одно правило на строку: `.env`, `*.key` (`*` — любые символы), `папка/`.
- Правила скрывают untracked-файлы из `git status` и пропускаются при `git add .`. На файлы, **уже закоммиченные**, не действуют — секреты вносить до первого коммита.
- `code .gitignore` — открыть файл из терминала (имя целиком, расширения нет).

| команда | что делает |
|---|---|
| `git check-ignore путь` | выводит путь, если файл игнорируется; пустой вывод — не игнорируется |
| `git check-ignore -v путь` | то же + `файл:строка:правило` — какое именно правило сработало |

Полезна, когда файл «почему-то не добавляется» или, наоборот, «почему-то не игнорируется». Файл может не существовать — Git смотрит только на имя.

### Права и remote

| команда | что делает |
|---|---|
| `git remote -v` | на какой адрес смотрит `origin` (свой репозиторий или чужой) |
| `git push --dry-run` | проверить, примет ли GitHub пуш, ничего не отправляя (при нехватке прав — 403) |

Чужой репозиторий напрямую не запушить: fork → пуш в свой fork → pull request. Права на свой репозиторий: на сайте Settings → Collaborators (потребует подтверждения по почте — sudo mode).

### Переименовать файл: `git mv`

| команда | что делает |
|---|---|
| `git mv старое новое` | переименовать **и сразу** добавить в индекс (в `git status` — зелёное `renamed: старое -> новое`) |
| `mv старое новое` | только переименовать на диске: в статусе ` D старое` + `?? новое`, пока не сделаешь `git add` на оба |

- Итог после коммита одинаковый: Git не хранит «переименование», а находит его по почти одинаковому содержимому.
- `git mv` работает только для **tracked** файлов. Для untracked — `fatal: not under version control`: либо `git add` и потом `git mv`, либо обычный `mv`.
- `fatal: bad source` — файла нет на диске (например, `code имя.py` открыл окно, но `Ctrl+S` не нажали).

### Исправить ошибку

| ситуация | команда |
|---|---|
| поменять сообщение последнего коммита (до push!) | `git commit --amend -m "новое"` |
| убрать файл из индекса (изменения остаются) | `git restore --staged файл` |
| выбросить изменения в файле (необратимо!) | `git restore файл` |

### Сообщения коммитов

- Глагол в повелительной форме: «Добавить…», «Исправить…», «Отметить…»
- Конкретика: **что** и **о чём**, а не «изменения» или «правки»
- Не повторять одно и то же сообщение — должно отличаться в `git log`
- Абсолютные даты и номера недель, а не «на след. неделю»

### Если что-то пошло не так

- `Connection was reset` при push — сетевой сбой, просто повторить `git push`.
- `LF will be replaced by CRLF` — безвредное предупреждение про окончания строк.
